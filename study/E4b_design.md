# E4-b 공통 상태 회복 평가 구현 규칙 (실행 전 고정)

- 작성: 2026-11-10. 근거: 명세 v0.13 3.8절, G-PRE 고정 문서 5절, T2 결과(`pilot/GPRE_T2T3_results.md`), 이탈 기록 D-MAIN-2(연구자 결정: G2 S_rec 21개 × 반복 3).
- 코드: `study/e4b.py`. 첫 E4-b 평가 전에 커밋한다.

## 1. 상태와 교란

- S_rec: G2 S8의 `srec.pkl` (SHA-256 `e0da26c550027e0548177696b64101df21fe910c1665e5de0ea234aae4357f5c`, 기준 정책 W1, 온도 0.6, 학습 조건). 원소 24개 중 S8 B부 타당 원소 21개.
- 교란 4종: 대조, R-a′(그리퍼만 열기, `Env.perturb`의 `R-a'`), R-b, R-c. T2 제외 규칙의 결과를 그대로 쓴다: R-c는 원소 5·19 제외(19개), 나머지는 21개. 제외 목록은 `pilot/artifacts/g2/gpre_t23/gpre_t2t3.json`에서 읽는다.
- 절차 (명세 3.8절, 확정): ① episode_id로 장면 재구성 ② 전체 상태(물리 + 제어기 + 과제 상태) 복원 ③ 교란 1회 ④ 회복 카운터 H = 40스텝. 성공 Y = 40스텝 뒤 (success ∧ 집기 래치).
- 백엔드: CPU PhysX, 환경 1개 (G-PRE 5절). 결과 이름은 "CPU 물리에서의 공통 상태 회복".

## 2. 정책과 반복

- 평가할 체크포인트: 각 E1 실행(모든 갈래·시드)의 최종 체크포인트, E3 실행의 최종 체크포인트, E2-b 분기의 최종 체크포인트. 출발 모델은 W1(E3는 W2) + 그 실행의 LoRA, 평가 경로(flash_attention_2, K0, 온도 0.6), unnorm `bridge_orig`.
- 반복: (원소 j, 교란 k, 반복 r)마다 샘플링 시드 1,000,000 + 10,000·r + 100·k + j (k = 대조 0, R-a′ 1, R-b 2, R-c 3; r = 0, 1, 2). **모든 체크포인트에 같은 시드**를 쓴다.
- 체크포인트당 롤아웃: (21 × 3 + 19) × 3 = 246회.

## 3. 출력·맹검

- 롤아웃 결과는 `<W>/blinded/<run_id>/e4b_<이름>.jsonl` (원소, 교란, 반복, Y, 성공, 래치, 기준 상태 물체 높이 범주)에만. 공개는 진행 수와 상태.
- 기술 보고 (G-PRE 5절): R-a′ 회복률을 기준 상태 물체 높이 ≥ 5 mm / < 5 mm로 나눠 낸다. 높이 범주는 T2 측정값(`z_above_t0_m`)에서 정한다.
- 분석: 지표 = 교란별 회복률(성공률), 회복 손실 = 대조 − 교란. E4-b A2⁺ − A3⁰이 보조 확증 ⑨ (명세 4.3·4.5절).

## 4. 실행 위치

러너가 GPU 작업 사이에 순차로 실행한다 (컨테이너 CPU 할당량이 4코어라 GPU 학습과 동시에 돌리면 학습이 느려진다). 1단계 실행(시드 1~4)의 E4-b는 2단계 계획의 앞에 넣는다.
