# A1 시연 SFT 재학습 설계 (2단계, 학습 전 고정)

- 작성: 2026-11-10. 근거: 명세 v0.13 3.3절(A1), 3.2절 C1~C3, 3.5절("A1은 튜닝하지 않는다. 원 SFT 레시피의 학습률·배치·스텝 수(60,000스텝)를 쓰고, C1·C2 통제만 바꾼다"), G-PRE 고정 문서 5번(안 A⁻: E1의 모든 학습은 결정적 경로).
- 원 레시피 출처: RL4VLA `README.md` SFT 절, `openvla/vla-scripts/finetune.py`, `openvla/rlds_dataset_builder/sft_dataset/sft_dataset.py`, `ManiSkill/.../motionplanning/widowx/collect_simpler.py`.
- 이 문서는 A1 학습을 시작하기 전에 커밋한다. 학습 시작 뒤 바꾸는 것은 `pilot/deviations.md`에 이탈로 기록한다.

## 1. 데이터

| 항목 | 원 레시피 | A1 | 이유 |
|---|---|---|---|
| 시연 생성 | `collect_simpler -e PutOnPlateInScene25Main-v3 --num_traj 16400 --seed=100 --num_procs 16` (성공 궤적만 저장) | 같은 명령, **프로세스 수 P = 메모리 한도 안의 값** (실제 값과 생성 집합 해시를 기록) | 이 인스턴스의 메모리 상한이 26 GiB라 16개 프로세스를 학습과 함께 돌릴 수 없다 (2026-11-10 컨테이너 재시작). 프로세스 p는 시드 p + 101을 쓰므로 P가 다르면 생성 집합이 원 저자의 것과 다르다. 원 집합은 어차피 공개되지 않았다 |
| 학습·검증 분할 | 파일 이름 정렬 → 앞 16,384 학습, 끝 16 검증 | 같음 | |
| 작은 행동 제거 (C3) | `filter_small_actions` (이동 < 0.01 그리고 회전 < 0.06이면 제거, 그리퍼 전환은 유지) | 같음 (원 함수 그대로) | C3: A1은 원 전처리 유지 |
| 성공 뒤 절단 | 성공이 6스텝 이어지면 그 뒤 버림 | 같음 | |
| 이미지 | tfds에 JPEG로 저장 → 디코드 → 224 × 224 | **JPEG 저장 생략**: 렌더 원본(480 × 640)을 그대로 정책의 전처리기에 넣는다 | 온라인 갈래와 같은 입력 경로. JPEG 압축 손실은 원 레시피의 저장 형식일 뿐 학습 설계가 아니다 |
| 행동 정규화 (C1) | SFT 데이터로 새로 계산한 `sft` 통계 | **`bridge_orig` 통계** (W1 체크포인트 config) | C1: 모든 갈래 통일 |
| 행동 → 토큰 | q01·q99로 [−1, 1] (그리퍼 차원은 정규화 안 함) → 자르기 → 256 bin `digitize` → 토큰 = 32000 − bin | 같음 (원 `ActionTokenizer` 식) | 환경의 역변환(`SimlerWrapper._process_action`)과 왕복 시험 |

## 2. 학습

| 항목 | 원 레시피 | A1 | 이유 |
|---|---|---|---|
| 출발점·LoRA (C2) | 병합 웜업 + 새 rank-32 LoRA, `all-linear`, gaussian | **병합 W1 + 온라인 갈래와 같은 LoraConfig**(원 PPO 레시피의 대상 모듈, rank 32, alpha 16, gaussian A·0 B), 초기화 시드 = 학습 시드 | C2 |
| 손실 | HF CE, 행동 토큰 7개 + 종료 토큰 평균 | **행동 토큰 7개의 NLL 평균** (A2⁺와 같은 `evaluate_actions` 경로, −Σ log π / 7) | 생성은 항상 7토큰이라 종료 토큰은 정책 행동에 쓰이지 않는다. 온라인 갈래와 같은 손실 계산 경로 |
| optimizer | AdamW(lr 5e-4, β 0.9·0.999, weight decay 0.01 기본값), 상수 학습률, 클리핑 없음 | 같음 | |
| 배치·스텝 | GPU 4개 × 8 = 32, 누적 1, 60,000스텝 | 32 (GPU 1개, 한 번에 나눠 계산해 합산), 60,000스텝 | 같은 전역 배치 |
| 표본 순서 | RLDS 셔플 버퍼(100,000) | 학습 프레임 전체를 에폭마다 시드(1,000 · 학습 시드 + 에폭)로 섞어 32개씩 | 균일 무작위 순서 (약 5에폭) |
| 증강 | 없음 (`--image_aug False`) | 없음 | |
| 수치 경로 | 원 코드 기본 | **결정적 math 경로** | 안 A⁻ (E1 갈래) |
| 시드 | — | 1, 2, 3 | 명세 4.5절 (보조 갈래 3개) |
| 저장 | — | 5,000스텝마다 latest(LoRA + Adam 상태, 재시작용), 60,000스텝 최종 | |

## 3. 평가·맹검

- 최종 체크포인트를 E1 평가 묶음(16조건 × 192, 고정 집합)으로 평가한다. 에피소드 결과는 `blinded/`에만 쓴다.
- A1은 주 비교에 들어가지 않는다 (기술 보고 A1 대 A2⁺, 명세 4.3절). 튜닝 예산이 다른 갈래와 다르다는 점은 한계로 기록한다 (명세 3.5절).
- 학습 손실은 `blinded/<run_id>/a1_loss.jsonl`에만 쓴다 (성공 정보는 아니지만 갈래 기록을 한곳에 둔다).

## 4. 비용 (추정)

GPU시간 ≈ 60,000스텝 × 32표본 × 표본당 순·역전파 시간(결정적 경로). 처음 500스텝에서 재고, 3회 합계가 150 GPU시간을 넘으면 시작 전에 연구자에게 알린다.
