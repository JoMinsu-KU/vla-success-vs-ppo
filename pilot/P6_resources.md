# P6 자원 추정 (4090 측정 기반, G2 전 1차)

- 일시: 2026-10-17
- 근거: 연구 명세 v0.9, 6.3절 P6, 7.3·7.4절. 측정은 모두 Windows 네이티브 RTX 4090 경로(CPU 시뮬레이션, 환경 1~3개)다. **본실험 경로(Linux H200·H100, GPU 시뮬레이션 64개)와 처리 구조가 달라 그대로 옮길 수 없다.** 이 문서는 (1) 4090에서 무엇이 가능한지, (2) G2에서 무엇을 재야 하는지를 정한다.

## 1. 측정치

| 작업 | 4090 Windows 측정 | 출처 |

| 평가 (배치 실행기, 환경 3개, LoRA 병합) | 9.1 s/에피소드 | speedup_and_batching.md |

## 2. 4090에서 본실험 규모를 돌릴 수 있는가 (외삽)

| 실행 | 4090 외삽 | 비교 |
|---|---|---|
| A2⁺ 1회 (390라운드) | 수집 14.0 + 학습 5.8 ≈ 20분/라운드 → **약 130시간** (오버헤드 포함 실측 속도면 약 190시간) | |
| PPO 1회 (390라운드, 32스텝/라운드) | 수집 14.0 + 학습 약 12.4분(32 × 23초) ≈ 26분/라운드 → **약 170시간** (value 경로 추가분 제외) | 원 논문 A100 1장 약 42시간 → 4090 경로가 **약 4배 느림** |
| 체크포인트 1개 평가 (16조건 × 192) | 3,072 × 9.1초 ≈ **7.8시간** | E1 26개면 약 200시간 |
| E1 기본 (온라인 22회 + 평가) | 약 4,000시간 이상 | 불가능 |

**결론:** 본실험은 계획대로 H200·H100(GPU 시뮬레이션)에서 한다. 4090은 파일럿·단위 시험·작은 진단 실행용이다. 특히 **평가 비용이 크다**: 4090에서 체크포인트당 7.8시간이고, 본실험에서도 E1·E2-b·E3 평가가 학습 롤아웃의 약 7배 스텝이다(명세 7.3절 평가 행). G2에서 GPU 시뮬레이션 64개 환경의 평가 처리량을 반드시 잰다.

## 3. G2에서 잴 것 (이 측정으로 정할 수 없는 것)

1. H200 GPU 시뮬레이션·렌더링 처리량: 수집 스텝/초 (환경 64개), 평가 에피소드/시간.
2. A3⁰ 50라운드 단기 학습: 라운드 시간, 학습 신호(critic 설명 분산, 성공률 추세는 δ 고정 전까지 가림, v0.9 4.2절).
3. A2⁺ 50라운드: 라운드 시간과 GPU 시간 비율(→ δ 대응 규칙).
4. 원 PPO의 라운드당 KL 분포 — **정확한 256 bin KL로** (P5에서 확인한 측정 방식 문제, P5_results.md).
5. W1 수집 성공률 재측정 (P3 잠정치 43.9%와 비교, 3.7절).
6. 생성 경로 대 teacher forcing 경로의 log-prob 차이 (P4 C10 후보)를 flash-attn 경로에서 다시 측정.

## 4. 저장 공간

| 항목 | 추정 |
|---|---|
| A2⁺ 1회 성공 궤적 원시 RGB 전량 보존 | 390 × 2.1 GB ≈ 820 GB (성공률이 오르면 증가) |
| PPO 1회 전체 롤아웃 원시 RGB | 약 1.84 TB (명세 7.4절과 일치) |
| 계층 저장(명세 7.4절) | 저차원 기록 약 2 GB + 보존 라운드 RGB 10~15 GB / 회 |

P5에서는 라운드 학습 뒤 원시 궤적을 지웠다. 본실험은 7.4절의 계층 저장을 그대로 쓴다.

## 5. 이 PC의 운영 제약 (파일럿 계속 시)

- GPU 24 GB 중 화면 출력 약 4 GB → 평가는 환경 3개까지, 학습은 미니배치 2.
- 시스템 RAM 64 GB 중 다른 프로그램이 약 34 GB → 2 GB 단위 배열 할당이 실패할 수 있음. 긴 실행 때는 다른 프로그램을 줄인다.
- Windows에서 렌더러·드라이버 수준 충돌이 드물게 생긴다 → 라운드 단위 재개 구조(p5_phased.py)를 쓴다.
