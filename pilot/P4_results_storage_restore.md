## 2. 저장 정확성 — **통과**

## 3. 재렌더링 일치율 (시뮬레이터 재현성 (i))

디스크에서 읽은 계층 1 상태로 복원한 뒤 다시 렌더링해 저장 RGB와 비교 (72 프레임):

| 측정 | 값 |
|---|---|
| 비트 단위 같은 프레임 | 1 / 72 |
| 다른 픽셀 비율 | 평균 0.003%, 최대 0.014% |

사실상 같다. 남는 차이는 접촉·속도 같은 숨은 물리 상태가 렌더링 전 갱신에 미치는 작은 영향으로 보인다.

## 4. 집기 접촉 상태 복원

### 4.1 상태 벡터 복원만으로는 부족

집기가 2스텝 이상 이어진 시점(에피소드 7개)의 전체 상태(물리 + 제어기 + 과제)를 복원하고 기록된 행동 25개를 재생:

| 비교 | 결과 |
|---|---|
| 원 궤적과 집기 상태 일치 | 7/7 에피소드 100% |
| 원 궤적과 info 일치 | 6개 100%, 1개 44% |
| 원 궤적과 상태 차이 | 첫 스텝부터 물체 속도에서 0.1~8.6, 25스텝 뒤 물체 pose 최대 1.1 (물체가 다른 곳으로 감) |
| **같은 저장 상태를 두 번 복원해 재생** | **7/7 비트 단위로 다름** |
| 대조군: pose만 복원 | 집기 일치 24~100%, 픽셀 7~23% 차이 (전체 복원보다 훨씬 나쁨) |

접촉 없는 상태(1차 시험)에서는 복원 뒤 차이가 1.5e-4 rad였다. 접촉 중에는 물리 엔진 내부 값(접촉 캐시, 솔버 warm start 등, 상태 벡터에 들어 있지 않음)이 결과를 바꾼다.

### 4.2 해결책 비교

같은 출발 상태를 세 번 만들고(사이에 다른 에피소드를 끼움) 같은 행동 25개를 재생:

| 방법 | 반복 재현 (비트 단위) | 원 궤적과 일치 | 출발 상태 준비 |
|---|---|---|---|
| 상태 벡터만 복원 | 불일치 (7/7) | 불일치 | — |
| **(a) 장면 재구성(`reconfigure=True`) + 전체 상태 복원** | **7/7 동일** | 불일치 | 0.28 초 |
| (b) 리셋 뒤 원 행동열 재생 | 불일치 | 불일치 | 1.4 초 |

**새로 확인한 사실:** 같은 환경 프로세스에서 앞서 돌린 에피소드의 이력이 리셋 뒤에도 물리 계산에 남는다. 그래서 (b)처럼 리셋부터 같은 행동을 재생해도, 사이에 다른 에피소드가 있었으면 결과가 다르다 (1차 시험의 "리셋부터 재실행은 비트 단위 동일"은 사이에 다른 에피소드가 없을 때였다). 장면 재구성만 이 이력을 지운다.

## 5. 설계 반영 제안

1. **E4-b 공통 상태의 정의:** S_rec = (episode_id, 전체 상태 벡터)이고, 평가 때마다 **장면 재구성 + 전체 상태 복원**으로 출발 상태를 만든다. 그러면 모든 정책이 비트 단위로 같은 출발 상태를 받는다. S_rec이 기준 정책의 원 궤적과 정확히 같은 상태일 필요는 없다 ("이 절차로 복원한 상태"로 정의).
2. **평가·수집의 재현성:** 에피소드마다 장면 재구성(약 0.28초, 에피소드 9초의 3%)을 하면 결과가 작업자 배치·실행 순서와 무관해진다. 고정 초기 상태 집합 평가(3.8절, v0.10)를 "같은 episode_id면 같은 출발 물리 상태"로 강화하려면 필요하다. 지금까지의 P2·P3·P5는 재구성 없이 실행했으므로, 같은 episode_id라도 숨은 물리 상태는 실행 순서에 따라 달랐다 (짝지은 비교는 물체·배치 구성에 대해서만 짝지어짐).
3. 본실험(Linux GPU 시뮬레이션, 환경 64개)에서 같은 성질이 성립하는지는 G2에서 확인한다. E4-b는 규모가 작으므로 CPU 시뮬레이션·환경 1개로 해도 된다.
