- 실행 방식: 명령은 연구자가 인스턴스에서 직접 실행하고, 단계마다 결과 파일을 저장소의 `pilot/artifacts/g2/<단계>/`로 올리거나 대화에 붙인다. 판정과 다음 단계 코드는 Claude가 결과를 보고 준비한다.

## 1. 목적과 원칙

G2는 **본실험에 자원을 넣을지 정하는 판단 단계**다. 적은 비용으로 아래 네 질문에 답하고, 답에 따라 계속·범위 변경·중단을 정한다.

1. H200에서 ManiSkill GPU 시뮬레이션과 렌더링이 되는가 (S2)
2. Linux 본실험 경로에서 원 논문의 RL > SFT(특히 실행 축)가 재현되는가 (S3·S4)
3. 통제 학습기가 본실험 규모에서 정상이고, 결정성·생성–학습 불일치·상태 복원이 어떤 상태인가 (S5~S8)
4. terminal PPO(A3⁰)에 학습 신호가 있는가, 그리고 한 번의 학습에 얼마가 드는가 (S9)

원칙:

- **순서대로, 앞 단계의 go/no-go를 통과해야 다음으로 간다.** S2·S3가 실패하면 포팅이나 학습에 자원을 쓰지 않는다.
- **GPU 시간 상한 60 GPU시간** (명세 5.1절 "G1 전 H200 사용 규칙"을 G2 전체에 그대로 적용). 단계별 배정은 2절 표. 넘기려면 이탈 기록(`pilot/deviations.md`)에 사유를 남기고 연구자가 승인한다.
- **맹검 (명세 4.2절):** S9의 A2⁺ 단기 실행은 δ가 고정될 때까지 비용 지표만 출력한다. A3⁰의 학습 신호는 사전 고정 스크립트가 "있음/없음"만 출력한다.
- **사전 고정:** S9 전에 3절 항목을 커밋하고 태그 `g2-prereg`를 단다. 결과를 본 뒤 기준을 바꾸지 않는다.
- 이 단계의 수치도 논문 근거가 아니라 설계·판정 근거다. 본실험 착수 승인은 G2가 아니라 G-PRE에서 한다.

## 3. S9 전에 사전 고정할 것 (태그 `g2-prereg`)

| 항목 | 제안 | 명세 근거 |
|---|---|---|
| 비용 → δ 규칙 | A2⁺ 1회 학습 GPU 시간이 A3⁰의 60% 이하 → δ 5%p, 60~85% → 4%p, 85% 초과 → 3%p | 4.2절 |
| A3⁰ 학습 신호 정의 | 라운드 1~R (R ≤ 50)에서 (a) critic 설명 분산: 마지막 10라운드 평균 − 처음 10라운드 평균 ≥ 0.05이고 마지막 10라운드 평균 > 0, **그리고** (b) 라운드별 수집 성공률의 OLS 기울기의 단측 90% 하한 > 0 (terminal 보상에서 수익 = γ^{T−1}·Y이므로 성공률과 같음). 둘 다 만족하면 "있음" | 5.1절 G2 |
| 신호 없음일 때의 순서 | 구현 점검 → (1-a) γ = 1 → (1-b) value 입력에 t/T → W2 → 범위 변경. (1-a)·(1-b)·W2 재시험은 60시간 상한 밖이므로 각각 이탈 기록과 승인 후 | 5.1절 |
| 맹검 출력 | A2⁺: 라운드 시간·GPU 시간·피크 메모리·optimizer 스텝 수만. 성공률·성공 수·손실 곡선은 δ 고정 전까지 별도 파일(해시만 기록) | 4.2절 |
| KL 장치 정의 | 고정 rollout-prefix 조건부 KL(π_round ‖ π_current), 탐침 상태 64개(라운드 배치에서 성공·실패 무관 균등), 위치 7개 합의 상태 평균. 기준 분포 = 통제 A3⁰의 라운드당 값, 참고 분위수는 G-PRE에서 | 3.3절 |
| A2⁺ 단기 실행 설정 | U-prop(성공 궤적 1회 훑기), lr 1e-4, KL 장치는 기록만 (상한은 G-PRE에서 정하므로) | 3.3·3.5절 |
| S_rec 타당성 기준 | 관절 한계 안, 물체–테이블·물체–그리퍼 관통 깊이 < 5 mm, 복원 직후 1스텝의 물체 속도 < 0.5 m/s, 래치 상태와 물리 접촉 일치. 교란 없는 복원 대조의 성공률이 원 궤적 성공률과 15%p 넘게 다르면 보고 | 3.8절 (기준값은 제안) |
| C10 민감도의 절단 | w̄ = clip(p₀/q₀, 0.5, 2) (joint 7토큰 단위) | 3.2절 C10 |

### S4 통제 평가 경로 (포팅 후)

같은 세 체크포인트를 본실험 평가 방식으로: 조건별 고정 `episode_id` 192개, 에피소드마다 장면 재구성, K0(top_k 0), 온도 0.6, 성공 = Y. 조건은 ID·실행 3·새 물체(우선), 시간이 남으면 16개 전체. S3와의 차이를 원 설정 대 통제 경로의 차이로 설명한다 (같아야 한다는 기준은 없다). GPU 시뮬레이션에서 64개 환경을 한꺼번에 재구성하는 비용이 크면(S2의 재구성 시간), 재구성 단위(배치마다 대 에피소드마다)를 바꾸지 말고 비용을 기록해 G-PRE에서 정한다.

### S5 처리량과 전체 규모 학습 계산 (G1 조건 2)

W1 + 새 LoRA로 환경 64개 1라운드(5,120전이)를 수집하고, 같은 배치에서:

1. **C9 전체 규모:** 원 코드형(joint log-prob 7칸 복제) 대 통제 학습기(joint 1개 × 계수 7)의 총 손실·기울기 상대 차이 (4090 기준 2e-8, 허용 1e-5 제안), 클리핑 뒤 기울기, 1회 업데이트.
2. **라운드 시간 분해:** 수집(시뮬레이션·렌더링·추론), old 값 재계산(C10), 업데이트 32스텝, 저장. 피크 GPU 메모리 (원 논문 보고 44.4 GB).
3. 결과가 허용 오차를 넘으면 **G1을 다시 연다** (D-006 조건).

### S6 C11 결정성과 비용

`pilot/learner/numerics.py`의 엄격 모드(`warn_only=False`)로 S5 배치에서:

- attention 경로 두 가지: (i) flash-attn 결정적 역전파, (ii) math SDPA. 각각 실제 선택된 경로를 기록.
- A/A: 새 시작점, 한 라운드 뒤(Adam 모멘트) 시작점에서 같은 업데이트 두 번 → LoRA·value head 비트 단위 동일.
- 비용: 기본(비결정) 설정 대비 라운드 시간 증가율 (4090: +30~45%).
- 엄격 모드 오류가 나면 연산 이름과 위치를 기록하고 멈춘다 (해결 방법은 Claude가 준비).

### S7 C10 잔여 생성–학습 불일치

W1과, S9 A3⁰의 라운드 10 체크포인트에서 **새로 수집한 배치**로 (재사용 배치는 정책 변화가 섞이므로 쓰지 않는다):

- 같은 관측·지시문·prefix에서 생성 경로와 teacher forcing 경로의 위치별 256 bin TV·KL
- 7토큰 joint log w = log p₀ − log q₀ 분포: 전체, advantage 부호별, Y별
- 보정 전후(w̄, 3절 절단) actor 기울기의 코사인과 1회 업데이트 Δθ 차이, 탐침 정책 변화
- 배치 크기·padding·position ID·LoRA 병합 여부·attention 경로 기록

판정하지 않고 기록한다. 처리 수준은 G-PRE에서 정한다.

### S8 상태 복원, S_rec 타당성, CPU–GPU 연결

- E4-b는 CPU 시뮬레이션·환경 1개로 할 수 있으므로 Linux CPU 경로에서 4090의 반복 재현 시험(장면 재구성 + 전체 상태 복원, 7개 이상)을 다시 한다. 실행 순서·작업자 배치를 바꿔도 비트 단위 동일해야 한다.
- 시험용 S_rec 24개(집기 단계 기준, W1 롤아웃에서)로 3절 타당성 기준을 적용하고 제외 수를 보고.
- CPU–GPU 연결 평가: W1·SFT·RL × 같은 시작 상태 24개 × 교란 3종 + 무교란 대조. 초기 전이, 성공 판정, 정책 간 상대 순서를 두 백엔드에서 비교.

### S9 단기 학습 — A3⁰ 신호와 비용

- A3⁰: 통제 학습기(C9·C10·C11 기본안), terminal 보상, W1 + 새 LoRA, 학습 시드 1개, 최대 50라운드. 라운드마다 저장: 라운드 시간, 수집 성공률(맹검 스크립트 입력), critic 설명 분산, 탐침 KL, C10 감사 요약, 체크포인트(라운드 10·50).
- A2⁺: 같은 조건, U-prop, 최대 50라운드. 출력은 비용 지표만 (3절).
- W1 수집 성공률 재측정: 두 갈래의 라운드 0 수집 (명세 3.7절 전환 규칙을 본실험 기기 값으로 다시 적용).
- 신호 판정: `g2_signal.py`(사전 고정, 태그 `g2-prereg`)가 "있음/없음"만 출력.
- 비용 외삽: 390라운드 1회 GPU 시간 (A3⁰·A2⁺), 결정적 설정 포함. 이 값으로 비용 → δ 규칙을 적용하고 E1 전체 예산표를 만든다.
